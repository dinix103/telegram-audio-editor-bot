# Telegram Audio Editor Bot

Русскоязычный Telegram-аудиоредактор на **Python / aiogram 3 / FFmpeg / Mutagen**.
Работает через **собственный Telegram Bot API в режиме `--local`**. Обработка вынесена
в отдельный worker; Redis хранит очередь и временное состояние, PostgreSQL — настройки
и обезличенные счётчики результатов.

**Статус: реализация для серверной приёмки, не подтверждённый production-релиз.**
Локальные тесты проверяют настоящие аудиофайлы. Реальные Telegram-загрузки и отправки,
Docker-развёртывание и нагрузка до 2 ГБ ещё требуют проверки на сервере владельца.
Точные результаты и оставшиеся проверки: [отчёт](docs/TEST_REPORT.md).

## Возможности

- Приём музыки, голосовых сообщений и документов; определение содержимого FFprobe.
- MP3, M4A/AAC, OGG/Vorbis, OGG/Opus, WAV, FLAC, AIFF и WMA.
- Музыкальные сообщения MP3/M4A, документы, голосовые OGG/Opus.
- Название, исполнитель, альбом, исполнитель альбома, год, жанр, номер трека/диска,
  композитор, комментарий, имя результата.
- Встроенные обложки ID3 / MP4 / FLAC picture / Vorbis picture: просмотр, загрузка,
  замена, удаление и извлечение JPEG. Изменения тегов без конвертации копируют исходный
  файл и записывают теги Mutagen, без запуска аудиокодера.
- MP3 128/192/256/320 кбит/с и авто; stream copy при совместимых контейнерах и кодеках.
- Обрезка, громкость с ограничителем пиков, нормализация, скорость 0,5–2×,
  удаление тишины на краях (записи до 10 минут).
- `/merge`: до 10 файлов с заданным порядком; `/batch`: одни правки для группы файлов.
- FSM, сводка перед сохранением, отмена, отдельные каталоги, лимиты, фоновые статусы.
- Настройки по умолчанию и `/admin` без доступа администратора к файлам пользователей.

## Быстрый запуск на Linux

Нужны Docker Engine с Compose v2, доступ к Telegram и достаточно диска.
Начальный ориентир — 4 vCPU, 8 ГБ RAM, 50 ГБ SSD. Это не гарантия обработки 2-ГБ задач.

```bash
git clone https://github.com/dinix103/telegram-audio-editor-bot.git
cd telegram-audio-editor-bot
cp .env.example .env
chmod 600 .env
# Заполните .env в редакторе
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

1. Создайте бота через [@BotFather](https://t.me/BotFather), `/newbot`; запишите токен в `BOT_TOKEN`.
2. Войдите на [my.telegram.org/apps](https://my.telegram.org/apps), создайте API application,
   заполните `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Это учётные данные API приложения,
   отдельные от токена бота.
3. Задайте длинный случайный `POSTGRES_PASSWORD` и тот же пароль в `DATABASE_URL`.
   Спецсимволы пароля в URL должны быть URL-encoded. Проще использовать случайный hex-пароль.
4. При необходимости укажите `ADMIN_IDS=[123456789]` — числовые Telegram ID администраторов.
5. Отправьте `/start` боту в личном чате. Групповые чаты намеренно не обслуживаются.

Никакие порты Compose не публикуются на хост. Только Bot API подключён к сети с выходом
в интернет. Приложение, FFmpeg, Redis и PostgreSQL находятся во внутренней Docker-сети.
Секреты не нужно вводить в GitHub, присылать в issue или коммитить.

### Если бот раньше использовал публичный API

Остановите прежний экземпляр, установите зависимости и выполните **до локального запуска**:

```bash
# BOT_TOKEN должен быть задан в окружении; скрипт не печатает его.
python tools/migrate_from_public_api.py
```

Скрипт вызывает официальный `logOut`. Это единственный намеренный вызов публичного API.
Основное приложение отказывается работать с `api.telegram.org`.
Подробнее: [официальный Bot API](https://github.com/tdlib/telegram-bot-api),
[подключение aiogram к своему серверу](https://docs.aiogram.dev/en/latest/api/session/custom_server.html).

## Использование

Отправьте файл → выберите правки → «Сохранить» → проверьте сводку → «Подтвердить».
Файл заново загружать для каждой правки не нужно. После доставки рабочая копия удаляется;
новая операция начинается с нового файла.

| Команда | Действие |
|---|---|
| `/start`, `/help` | Главное меню и помощь |
| `/settings` | Формат, MP3-битрейт, отправка, перенос тегов, обложки, подтверждение |
| `/merge` | Сбор файлов для объединения; отправляйте по одному после окончания анализа |
| `/order` | Все номера файлов через пробел, например `3 1 2` |
| `/batch` | Сбор файлов для одинаковой обработки |
| `/cancel` | Отменить сессию или запросить остановку worker |
| `/delete` | Отмена, удаление рабочих файлов, временного состояния и настроек |
| `/privacy` | Условия временного хранения |
| `/admin` | Состояние сервисов, счётчики, очередь и свободный диск |
| `/admin pause`, `/admin resume` | Остановить / возобновить приём новых файлов |
| `/admin limit 500` | Временный лимит входного файла в МБ, в пределах серверного максимума |

## Ограничения и честные гарантии

- Лимит результата — **2 000 000 000 байт**; это консервативная настройка в пределах
  локального Bot API. Дисковая квота задачи по умолчанию — 6 ГБ, резерв — 2 ГБ.
- Одна активная сессия на пользователя; один тяжёлый процесс на worker. Параллелизм
  разных пользователей увеличивается числом workers, после измерения RAM и диска.
- Редактор тегов/обложек для raw AAC и WMA не поддерживается. Конвертация аудио работает;
  интерфейс предупреждает о потере несовместимых метаданных. Для правок выберите MP3/M4A/FLAC/OGG.
- WAV/AIFF используют ID3; некоторые внешние плееры такие теги/обложки не показывают.
- Повышение битрейта не улучшает исходное качество. Эффекты и объединение требуют декодирования.
- Объединение приводит входы к PCM 48 кГц stereo; для него нужен дополнительный диск.
  Объединённый файл наследует теги и обложку первого загруженного файла.
- Пакет отправляется последовательно. При ошибке следующие результаты не отправляются;
  уже доставленные сообщения остаются в Telegram. После ошибки загрузите оставшиеся файлы заново.
- После сбоя worker задача не отправляется автоматически повторно: это исключает
  неконтролируемые дубликаты сообщений. Остатки удаляются, пользователь повторяет загрузку.
- `/cancel` останавливает FFmpeg; отправка, уже принятая Telegram, может завершиться.
- `/delete` удаляет рабочую копию редактора, но не сообщения, устройства пользователей
  и отдельный кэш Bot API. [Политика хранения](docs/PRIVACY.md) описывает различия.
- Полное соответствие критериям приёмки нельзя заявлять до серверных и клиентских испытаний.

## Тесты и разработка

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
pip install -e '.[test]'
# Установите ffmpeg и ffprobe в PATH
pytest -q
ruff check audio_bot tests tools
```

`FFMPEG` и `FFPROBE` могут указывать на отдельные исполняемые файлы. Без них медиа-тесты
помечаются `skipped`, поэтому такой запуск не подтверждает работу конвертации.
Тесты генерируют синусоидальные WAV/MP3/M4A/Opus и проверяют реальные результаты,
включая идентичность декодированного звука до/после редактирования тегов.
GitHub Actions устанавливает FFmpeg, запускает тесты, проверяет Compose и собирает приложение.

## Обновление

```bash
# Сначала /admin pause и дождаться завершения задач
git pull --ff-only
docker compose up -d --build
docker compose ps
# Затем /admin resume
```

Миграция `migrations/001_initial.sql` применяется под PostgreSQL advisory lock при запуске.
Для резервных копий разрешены только настройки и агрегированные счётчики PostgreSQL.
Volumes `jobs`, `telegram` и Redis исключите из резервного копирования и снапшотов хоста.
