# Отчёт проверки — 4 ноября 2026

## Выполнено локально

Окружение: Windows, Python 3.13.2, FFmpeg/FFprobe 9.0.2 (Gyan Windows essentials).
Медиа- и прикладные тесты: **53 passed**. Дополнительный тест настоящих Redis/PostgreSQL
локально пропускается, поскольку здесь нет этих сервисов; в CI он включён.
`ruff` проверяет исходники, тесты и инструменты.
Использованы настоящие сгенерированные синусоидальные аудиофайлы, не имитация кодека.

Проверены:

- Opus → MP3, MP3 ↔ M4A, FLAC → MP3, WAV → Opus/FLAC, MP3 → OGG/WAV,
  AAC/AIFF/WMA → MP3 и создание голосового Opus.
- Теги и встроенные обложки MP3, M4A, FLAC, OGG, Opus, WAV, AIFF: добавление,
  чтение, удаление; перенос тега при конвертации.
- SHA-256 декодированного PCM совпадает до/после изменения только тегов/обложки.
- Обрезка + скорость + громкость + нормализация; объединение MP3 и WAV в заданном порядке.
- Анализ → обработка → доставка → удаление для одиночной, пакетной и объединённой задачи.
  **Telegram-транспорт в этих тестах заменён тестовым объектом; это не проверка реальной отправки.**
- Повреждённые файлы, поддельное расширение, неверные изображения/интервалы, превышение
  лимита результата, отсутствие свободного места, тайм-аут, отмена subprocess.
- Изоляция владельцев, состояние очереди, активные lease/heartbeat, TTL-очистка,
  отменённые задачи, аварийные каталоги после потери состояния Redis.

Redis в локальных тестах — fakeredis; PostgreSQL и Telegram в worker-тестах — тестовые
транспорты. GitHub Actions дополнительно поднимает реальные Redis/PostgreSQL для проверки
миграции, настроек, BLMOVE, lease и удаления сессии. Статус конкретного запуска CI следует
проверять на вкладке Actions; наличие workflow само по себе не означает успешное прохождение.

## Серверная приёмка

1. Запустить Compose с тестовым ботом, проверить healthchecks и приватность сети.
2. Пройти функциональные сценарии раздела 16 ТЗ двумя независимыми Telegram-пользователями.
3. Для каждого размера из таблицы записать фактические байты, формат, длительность,
   время загрузки/обработки/отправки, пиковую RAM и минимум свободного диска.
4. Проверить теговую правку и конвертацию отдельно; для WAV/FLAC заранее учесть рост результата.
5. Повторить с одновременными пользователями, отменой и перезапуском worker.
6. Искусственно ограничить место на **тестовом** volume и убедиться в корректном отказе.
7. Убедиться, что рабочие файлы удалены после успеха, отмены, TTL и аварии; проверить
   независимость кэша Bot API. Проверить offline-ротацию на выделенном тестовом экземпляре.
8. Добавить результаты в этот документ, указав сервер, версии и фактические ограничения.
