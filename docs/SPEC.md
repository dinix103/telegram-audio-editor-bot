# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Telegram Audio Editor Bot — универсальный редактор аудиофайлов

**Версия:** 1.0  
**Тип проекта:** Telegram-бот  
**Язык интерфейса:** русский  
**Платформа:** Telegram (Android, iOS, Desktop, Web)  
**Основной стек:** Python, aiogram 3, FFmpeg, Mutagen, PostgreSQL, Redis, Docker  
**Обязательная инфраструктура:** Self-hosted Telegram Bot API Server

---

## 1. Общая концепция

Необходимо разработать современного Telegram-бота, позволяющего пользователям конвертировать аудиофайлы, редактировать их метаданные, заменять обложки, обрезать записи и выполнять другие операции непосредственно в Telegram.

Бот должен работать с обычными музыкальными файлами, голосовыми сообщениями Telegram, аудиозаписями WhatsApp и файлами, загруженными пользователем с устройства.

### Основные принципы

1. Максимально простой и понятный интерфейс.
2. Никакой обязательной регистрации.
3. Все операции выполняются внутри Telegram.
4. Поддержка больших файлов через локальный Bot API Server.
5. Сохранение исходного качества, когда возможно.
6. Возможность выполнять несколько изменений перед сохранением.
7. Конфиденциальность пользовательских данных.
8. Автоматическое удаление временных файлов.
9. Стабильная работа при одновременном использовании несколькими пользователями.
10. Возможность расширения функциональности без переписывания архитектуры.

## 2. Приём файлов

Бот должен принимать:

- Музыку, отправленную как аудиосообщение Telegram.
- Голосовые сообщения Telegram.
- Аудиозаписи WhatsApp, пересланные или загруженные в Telegram.
- Аудиофайлы, отправленные как документы.
- Файлы с компьютера или телефона.

### Поддерживаемые форматы

| Формат | Чтение | Конвертация в формат |
|---|---|---|
| MP3 | Да | Да |
| M4A / AAC | Да | Да |
| OGG / Opus | Да | Да |
| WAV | Да | Да |
| FLAC | Да | Да |
| WMA | Да | Желательно |
| AIFF | Да | Желательно |

Нужно определять действительный формат файла через FFprobe, а не полагаться только на его расширение.

После получения файла бот должен показывать:

- Название и исполнителя, если указаны.
- Обложку, если присутствует.
- Формат и аудиокодек.
- Длительность.
- Размер файла.
- Битрейт.
- Частоту дискретизации.
- Доступные действия.

Если файл повреждён или его формат не поддерживается, выводить понятное сообщение на русском языке.

## 3. Редактирование метаданных

Реализовать полноценный редактор аудиотегов.

### Редактируемые поля

1. Название композиции (Title).
2. Исполнитель (Artist).
3. Альбом (Album).
4. Исполнитель альбома (Album Artist).
5. Год выпуска (Year / Date).
6. Жанр (Genre).
7. Номер трека (Track Number).
8. Номер диска (Disc Number).
9. Композитор (Composer).
10. Комментарий (Comment).
11. Название выходного файла.

Пользователь может менять поля по отдельности или несколько подряд.

### Обложки

Реализовать следующие возможности:

- Просмотр текущей обложки.
- Загрузка новой обложки фотографией или изображением.
- Замена существующей обложки.
- Удаление обложки.
- Извлечение существующей обложки в JPEG/PNG.
- Автоматическое приведение изображения к совместимому формату и размеру.

Обложка должна встраиваться в метаданные файла, если целевой формат поддерживает соответствующий способ хранения.

**Важно:** нельзя ограничиваться установкой превью сообщения в Telegram. Обложка должна сохраняться внутри самого музыкального файла.

Для MP3 использовать ID3, для M4A — MP4-теги, для FLAC — picture blocks, для OGG/Opus — поддерживаемые механизмы метаданных. Если конкретная комбинация тегов и формата не поддерживается, необходимо сообщить об этом пользователю.

### Сохранение качества

Изменение названия, обложки, альбома, исполнителя и других тегов не должно приводить к перекодированию аудиопотока.

При редактировании метаданных требуется сохранять исходный аудиокодек и качество, если формат и библиотека позволяют это сделать.

Все изменения сначала сохраняются в состоянии текущей сессии. Физическое применение выполняется при нажатии «Сохранить».

## 4. Конвертер аудио

Реализовать конвертацию между поддерживаемыми форматами с помощью FFmpeg.

### Возможности

- MP3 → M4A, OGG, WAV, FLAC и другие форматы.
- M4A → MP3.
- OGG / OPUS → MP3.
- MP3 → OGG / OPUS.
- WAV → MP3.
- FLAC → MP3.
- Конвертация голосовых сообщений Telegram и WhatsApp в обычные музыкальные файлы.
- Создание голосового сообщения Telegram из аудиофайла.

### Выбор качества

Для MP3 предусмотреть:

- 128 кбит/с.
- 192 кбит/с.
- 256 кбит/с.
- 320 кбит/с.
- Автоматический режим.

Для других форматов предусмотреть подходящие настройки кодека.

### Дополнительные требования

- Проверять целевой формат и возможность конвертации.
- Показывать прогнозируемое изменение качества.
- Не обещать улучшение исходного качества при увеличении битрейта.
- При совместимости контейнеров и кодеков использовать stream copy без перекодирования.
- Не выполнять промежуточные конвертации без необходимости.
- Сохранять совместимые метаданные при конвертации.
- Для форматов без поддержки обложек объяснять ограничения.
- Для несжатых файлов предупреждать о возможном значительном увеличении размера.

### Отправка результата

MP3 и M4A отправлять музыкальным сообщением Telegram, когда это возможно.

Остальные форматы отправлять документом, сохраняя расширение и имя файла.

Для голосовых сообщений использовать совместимое представление, предпочтительно OGG/Opus, и соответствующий метод Telegram API.

Предусмотреть переключатель:

- Отправить как музыку.
- Отправить как файл.
- Отправить как голосовое, если совместимо.

## 5. Инструменты обработки звука

### 5.1. Обрезка

Пользователь должен уметь выбирать начало и конец фрагмента.

Пример:

Начало: 00:15  
Конец: 01:45

Бот обрезает запись и возвращает результат.

Необходимо проверять корректность интервала.

### 5.2. Объединение файлов

Пользователь отправляет несколько аудиофайлов, задаёт порядок и получает один объединённый файл.

При необходимости производится конвертация к совместимым параметрам.

### 5.3. Изменение громкости

Варианты:

- Уменьшить громкость.
- Увеличить громкость.
- Нормализовать громкость.

Предотвращать чрезмерный клиппинг и предупреждать об искажениях.

### 5.4. Изменение скорости

Предусмотреть коэффициенты:

- 0,5×
- 0,75×
- 1×
- 1,25×
- 1,5×
- 2×

По возможности сохранять высоту тона при изменении скорости.

### 5.5. Удаление тишины

Дополнительная функция: автоматическое удаление тишины в начале и конце записи.

### 5.6. Пакетная обработка

На втором этапе разработки предусмотреть возможность отправить несколько файлов, выбрать одну операцию и применить её ко всем выбранным файлам.

## 7. Локальный Telegram Bot API Server

**Обязательное требование. Использование только публичного `api.telegram.org` в качестве основного канала обработки недопустимо.**

### Реализация

Использовать официальный сервер:

https://github.com/tdlib/telegram-bot-api

Сервер разворачивается самостоятельно и запускается в режиме `--local`.

Для работы необходимы:

- TELEGRAM_API_ID.
- TELEGRAM_API_HASH.
- BOT_TOKEN.

Все секреты получать через переменные окружения или защищённое хранилище.

aiogram должен обращаться к локальному Bot API Server через собственную конфигурацию HTTP-сессии с включённым локальным режимом.

### Работа с файлами

1. Максимально возможный размер отправляемого результата — 2000 МБ в рамках ограничений локального Bot API.
2. Скачивание входных файлов — без ограничения размера со стороны локального `getFile`, но с контролем собственных ресурсов.
3. Не загружать большие аудиофайлы целиком в оперативную память.
4. Использовать файловые пути и потоковую обработку.
5. Организовать общий доступ к нужным файловым каталогам между Bot API Server и обработчиком.
6. Проверять доступность локальных путей.
7. Не использовать публичные ссылки для передачи приватных пользовательских файлов между компонентами.
8. Реализовать проверки свободного места и квоты.
9. Не допускать отправки результата, превышающего лимит Telegram.

При переводе существующего бота с публичного API выполнить корректный `logOut` до переключения.

### Разделение данных

Необходимо различать:

- Файлы, принадлежащие самому Telegram Bot API Server.
- Рабочие файлы аудиоредактора.
- Временные результаты FFmpeg.
- Состояние пользовательской сессии.

Очистка рабочих файлов не должна удалять служебные файлы Telegram Bot API Server или нарушать его работу.

Для файлов, которыми управляет сам Bot API Server, реализовать и документировать отдельную безопасную политику хранения и очистки.

## 8. Приватность и безопасность

Приватность — одна из основных характеристик проекта.

### 8.1. Хранение

- Аудиозаписи не сохраняются в постоянной базе данных.
- Не отправляются на сторонние сервисы обработки.
- Не используются для аналитики или обучения ИИ.
- Не передаются администратору бота.
- Не создаются постоянные общие каталоги пользовательских файлов.
- Не включаются в резервные копии.
- Не отправляются в системы мониторинга и логирования.

Допускается временное хранение на собственном сервере только для выполнения запрошенной операции.

### 8.2. Изоляция пользователей

Для каждой операции создаётся отдельный случайно именованный рабочий каталог.

Например:

`/app/tmp/jobs/<random_job_id>/`

Нельзя использовать пользовательское имя файла как часть пути без нормализации.

Один пользователь не должен иметь возможность получить файлы или результаты другого.

### 8.3. Автоматическое удаление

Реализовать три механизма:

**Обычная очистка:**

После успешной доставки результата и завершения задачи удалять рабочие исходники, промежуточные файлы и результат обработки.

**Очистка по таймеру:**

При бездействии пользователя более 15 минут завершать неактивную сессию и удалять её рабочие файлы.

Активная операция обработки или отправки не должна удаляться по этому правилу.

**Аварийная очистка:**

Периодический процесс должен находить и удалять оставшиеся файлы завершённых, отменённых и зависших задач. Целевой срок очистки — не позднее одного часа после признания задачи неактивной.

Приложение должно корректно восстанавливаться после перезапуска и выполнять очистку незавершённых временных каталогов.

### 8.4. Команды приватности

`/privacy` — объяснение обработки и хранения данных.

`/delete` — отмена текущих задач пользователя, удаление его рабочих файлов и очищение связанных временных состояний.

`/cancel` — отмена текущего действия.

Важно: удаление локальных файлов не означает автоматического удаления копий сообщений и вложений, которые могут сохраняться в инфраструктуре Telegram или на устройствах пользователей. Бот не должен обещать обратное.

### 8.5. Безопасность обработки

- Не передавать пользовательские строки в shell-команды.
- Запускать FFmpeg через безопасный API subprocess без `shell=True`.
- Ограничивать разрешённые протоколы, форматы и ресурсы FFmpeg.
- Не позволять медиафайлам инициировать произвольные сетевые запросы.
- Проверять содержимое, размер и тип входных файлов.
- Ограничивать использование CPU, RAM, диска и время обработки.
- Запускать обработчики с минимальными правами.
- Использовать контейнерную изоляцию.
- Не открывать локальный Bot API Server в публичный интернет.
- Не записывать BOT_TOKEN, API_HASH, содержимое файлов и персональные данные в логи.
- Ограничить доступ к административным функциям.
- Обрабатывать попытки path traversal, поддельные расширения и повреждённые медиафайлы.

## 9. Архитектура и технологии

### Backend

Python 3.12+ и aiogram 3.

Для обработки использовать:

- FFmpeg — аудиоконвертация и обработка.
- FFprobe — анализ файлов.
- Mutagen — аудиотеги и обложки.
- Pillow — изображения.
- PostgreSQL — настройки, технические данные и минимальная история задач.
- Redis — очередь, состояния и краткосрочные данные.
- Отдельный Python worker — выполнение тяжёлых задач.

Допускается использование Celery или другого надёжного механизма фоновых задач.

### Архитектура

Telegram Client  
↓  
Self-hosted Telegram Bot API Server  
↓  
Bot Application (aiogram 3)  
↓  
Redis / Queue  
↓  
Audio Processing Workers  
↓  
FFmpeg / Mutagen / Pillow  
↓  
Local Bot API Server  
↓  
Результат пользователю

PostgreSQL использовать только для необходимых записей, не сохраняя содержимое пользовательских аудиофайлов.

### Разделение компонентов

Предусмотреть независимые модули:

- bot — Telegram-обработчики.
- keyboards — интерфейс.
- states — сценарии и FSM.
- services/metadata — метаданные.
- services/converter — конвертация.
- services/audio — аудиоэффекты.
- services/covers — обложки.
- services/files — безопасные файловые операции.
- workers — тяжёлые задачи.
- database — модели и миграции.
- cleanup — очистка.
- config — настройки.
- tests — автоматические тесты.

Не размещать всю бизнес-логику в одном файле.

## 10. Производительность и ограничения

### Конкурентная работа

- Поддержка нескольких пользователей одновременно.
- Независимые сессии.
- Очередь тяжёлых операций.
- Контролируемое количество параллельных FFmpeg-процессов.
- Предотвращение переполнения диска.
- Отмена задач.
- Тайм-ауты.
- Корректное восстановление после рестарта.

### Рекомендуемая конфигурация сервера

Начальный ориентир:

- Linux VPS, предпочтительно Ubuntu LTS.
- От 4 vCPU.
- От 8 ГБ RAM.
- От 50 ГБ SSD/NVMe.
- Docker и Docker Compose.

Эта конфигурация не гарантирует одновременную обработку нескольких файлов по 2 ГБ. Фактические требования нужно определить нагрузочными тестами.

Ограничить число одновременных тяжёлых операций исходя из свободных ресурсов.

### Дисковая политика

При обработке больших файлов учитывать место под:

- Исходник.
- Результат.
- Промежуточные данные.
- Кэш локального Bot API Server.

Перед запуском задачи проверять достаточность места с запасом.

Начальный лимит для пользователя: одна активная тяжёлая операция. Значение должно настраиваться.

## 11. Стабильность и обработка ошибок

Бот не должен аварийно завершаться из-за отдельного повреждённого аудиофайла.

Предусмотреть обработку:

- Повреждённых файлов.
- Некорректных метаданных.
- Отсутствующих аудиопотоков.
- Превышения размера.
- Нехватки дискового пространства.
- Ошибок FFmpeg.
- Ошибок передачи результата.
- Перезапуска контейнеров.
- Потери соединения с Telegram.
